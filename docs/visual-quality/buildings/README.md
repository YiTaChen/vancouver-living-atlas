# Stage 3: coherent building facades

The 7,800 measured building parts retain their source footprint, foundation rule and vertical interval. A shared definition assigns each of 3,372 structures one of five representative architectural treatments: heritage brick, low-rise masonry, mid-rise grid, balcony slab and curtain wall. These are visual categories inferred from height, location, footprint and a stable source ID; they are not surveyed building-use classifications. Changing source array order no longer changes a structure's facade style.

Each wall fits a symmetric set of bays. Glass, roughness, night lighting and masonry normal exclusion use one window mask; nearby stone surrounds, slab lines, mullions and balcony posts use the same bay/floor dimensions. Elevated building parts now use physical `minHeight → height` UV coordinates, preserving floor spacing instead of compressing it into the shorter wall. Partial windows at part boundaries are omitted. Ordinary buildings also retain a ground-floor window band above the maximum sampled frontage grade, avoiding a blank first storey. This shader band is representative glazing, not an entrance; heritage shopfronts use the independently checked physical entry geometry. Different glass/wall roughness and subdued masonry relief use existing original textures, with no imported finished model or fixed-window texture overlaid on the new grid.

Gastown entries sample actual sidewalk triangles at both jambs and the centre. An entry is omitted when the samples are missing, obstructed, too steep or leave inadequate clearance below the first upper window. Valid shopfront glass, sill and compact fascia now sit at that threshold instead of the building-centroid ground level. Generic shop names remain illustrative. Roof equipment shares the same structure foundation and stable identity.

The city body remains a shared material and batched geometry; windows remain shader patterns. Physical high-rise accents retain the existing nearby-cell selection and bounded cache. This pass does not create hundreds of thousands of individual window meshes. The [layout census](layout-census.json) records the source types and potential pane counts. A [CPU geometry audit](body-validation.json), using the real footprints and a deterministic sloped test surface, checks every generated vertex, foundation and physical UV; all vertices are finite, with Float32 XY error below 0.123mm. That audit is separate from browser rendering/performance evidence.

## Validation

The TypeScript check and all 160 regression tests pass. Tests include stable structure grouping, short/reversed wall layouts, frame/mask alignment, elevated-part floor phase, material separation, street-level entry clearance, and the existing facade-cache bounds. The test module loader and fixture now provide the shared profile dependency rather than an obsolete independent facade style.

Real browser captures and timing comparisons are recorded in [stage-3-buildings](../stage-3-buildings/README.md). The QA build is excluded by the normal Firebase build verifier. Building geometry is preserved, but these ordinary facades remain representative detail; named-landmark reconstruction is scheduled separately.

At the same 1920×1080 viewport, final High samples are 39.9 FPS downtown, 36.4 FPS on the approximately 141m Robson drive, and 28.4 FPS at Water Street. None has a >100ms frame; Water Street still has an 85.1ms maximum and remains below the roughly 30 FPS target. Ultra is 22.5 FPS driving and 19.1 FPS walking, with one 148.3ms driving interval. These remain short diagnostics; stage 9 must address cold construction and frame-time spikes. Actual daytime and nighttime browser views show aligned windows, preserved complete models and no shader errors. The report's parent revision is `f40d185` plus this stage's working changes; the CPU report also records source hashes.
