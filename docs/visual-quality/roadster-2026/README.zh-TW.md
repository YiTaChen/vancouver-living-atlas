# 2026 Roadster：近景模型與遊戲執行版本比較

這次採用新製作的 Roadster 外觀與座艙細節，並保留 Vancouver Living Atlas 已有的操作介面、三階品質、動態零件、接地及相機流程。高面數展示模型是細節來源；網站使用另外整理的執行期資料，不能把展示用 GLB 的面數、材質或 Blender 渲染效果直接當成網站成品。

## 可重現的同條件比較

在專案根目錄執行：

```sh
ROADSTER_BASELINE_REF=53bb3c619a160627cb9b4394e9876f36c6f2323a node tools/preview-tesla-roadster-comparison.mjs
python3 -m http.server 5189 --bind 127.0.0.1
```

開啟 `http://localhost:5189/work/tesla-roadster-comparison/`。建置需要本機 Git 物件、Three.js 及 TypeScript；瀏覽器檢視時只使用產出的本機模組。產物位於被忽略的 `work/`，不加入 `public/`，舊版比較模型也不打包進正式應用程式。

工具未設定環境變數時預設解析 `origin/main`；本報告的固定基準是 `53bb3c619a160627cb9b4394e9876f36c6f2323a`，上方指令可避免遠端分支移動影響重現。工具從該 commit 取得整合前的 TypeScript 依賴圖，再讀取目前工作樹的整合後依賴圖。若要重現另一基準，可設定 `ROADSTER_BASELINE_REF`。每次重新建置會產生：

- `index.html`：整合前、整合後及並排檢視，低／中／高品質，前方、車側、車尾、底盤、座艙與屋頂剖視。
- `evidence.json`：基準 commit、目前 commit、工作樹狀態、每個實際依賴檔案的 SHA-256、尺寸、錨點、可見幾何包圍盒及三階成本。
- `REPORT.md`：本次建置實測的兩版三階成本表，方便檢查與保存。

相對 TS／JS／JSON 依賴會遞迴整理成瀏覽器可讀的模組；不需要手動列出新增的幾何 JSON。遇到無法解析的依賴或未允許的外部套件，工具會明確失敗。

比較頁的 URL 保存 `mode`、`quality`、`view`，方便用相同條件重開。例如：

```text
?mode=split&quality=high&view=three
?mode=split&quality=high&view=roof
?mode=split&quality=high&view=native-eye
?mode=split&quality=medium&view=cabin
```

`window.roadsterComparison` 暴露模型、相機、測量資料及 `getState()`，供人工瀏覽器驗收查核；頁面成功繪製兩幀後，`document.documentElement.dataset.ready` 為 `true`。載入失敗會在頁面顯示錯誤。

## 比較條件與可解讀範圍

兩版固定使用相同半球光、兩盞方向光、ACES 色調映射、曝光 1.05、輸出色彩空間、抗鋸齒及最高 1.5 的像素比。兩版都以輪胎接地平面為原點，保留公尺單位，不重新縮放、置中或自動取景。外觀與剖視使用完全相同的鏡位、目標、視角及等寬 viewport。固定外觀鏡位已投影檢查兩版的保守碰撞範圍：在 1280×720 並排、每側 640×720 的畫面內，前 3/4、正前、車尾及車側都完整入鏡，最小水平餘量超過 52px；確切鏡位與各方向餘量見 `measurements.json`。

座艙提供三種有不同用途的檢查：

| 控制            | 相機規則                                                   | 用途                                                                 |
| --------------- | ---------------------------------------------------------- | -------------------------------------------------------------------- |
| 座艙 · 各版眼位 | 各自的 `driverEye`／`driverLookAt`，相同 70° FOV，固定鏡位 | 檢查兩版實際宣告的駕駛視線；位置不同，不能當作完全相同鏡位的外觀比較 |
| 共同舊眼位      | 兩版都使用舊版錨點                                         | 顯示新車頂、儀表板與舊相機高度的關係                                 |
| 共同新眼位      | 兩版都使用新版錨點                                         | 從新版實際位置比較方向盤、前擋及座艙結構                             |

屋頂剖視對兩版使用同一個世界座標 `Y ≤ 0.94m` 裁切平面，用於查看椅墊、中央鞍座及門板。這是檢查用剖面，會裁切穿過該高度的其他零件，不能當作可移除車頂或開門功能已整合的證據。執行期若只提供關閉的車體，不會為展示而隱藏整批碳纖維或玻璃網格。

材質保留兩版實際執行期設定。比較頁不使用 HDRI、城市後製、陰影或 Blender 程序紋理；因此能比較相同基本照明下的輪廓、零件、縫隙與 PBR 反應，不能代表所有城市天候或原生 `.blend` 的織物效果。

## 成本證據

以固定基準和目前執行期實際建立的三階結果比較：

| 品質 | 整合前三角形 | 整合後三角形 |   變化 | 舊幾何 buffer bytes | 新幾何 buffer bytes |
| ---- | -----------: | -----------: | -----: | ------------------: | ------------------: |
| 低   |       10,590 |       10,777 | +1.77% |             762,480 |             443,445 |
| 中   |       27,140 |       28,516 | +5.07% |           1,954,080 |             967,434 |
| 高   |       58,922 |       54,249 | -7.93% |           4,242,384 |           1,567,062 |

兩版每階都是 35 個車體網格／35 個可見幾何批次，`stats()` 均為 13 個材質（含噴氣材質）。新版由 34 個資料批次加 1 個示意前側噴口批次構成；噴氣開啟再增加 1 個固定實例繪製批次。地板屬於檢視工具，不計入模型成本。

這些是 `createTeslaRoadster()`／`stats()` 與實際 BufferGeometry 陣列的測量。此報告快照保存在 `measurements.json` 和 `REPORT.md`；重新建置則更新 `work/tesla-roadster-comparison/` 的同類資料。來源 SHA-256 可辨識實際受測版本，即使工作樹尚未提交，也不把不同版本混成同一張表。

### 初始載入取捨

新版不是零成本換殼。基準以約 42,952 bytes 的三個 TypeScript 來源程序生成形體，沒有對應 JSON 幾何檔；新版的靜態幾何 JSON 為 **2,194,905 bytes**，該檔獨立 gzip 後 **981,500 bytes**，量測 JSON 另有 **14,292 bytes**（gzip **2,054 bytes**）。本次完整 TS／JSON 來源圖為 2,231,606 bytes，各來源檔分別 gzip 的加總為 991,428 bytes；基準對應加總為 13,512 bytes。這是來源檔稽核，不是正式 minified bundle 大小或觀測到的網路傳輸量。 最後修正保留所有非輪胎資料，替換了有缺口的精簡胎面；新胎面另通過中央支撐與任意旋轉相位的接地檢查。

三階的封裝字串以靜態 JSON 依賴隨城市 chunk 載入並解析；第一次建立或切到某階時，才同步執行 base64／量化資料解碼、產生 typed array 與幾何界線，之後重用快取。位置、法線解碼為 Float32，顏色使用正規化 Uint8，索引使用 Uint16。這降低了目前量到的幾何陣列成本，卻增加了初始程式資料量及首次解碼工作；目前沒有量測瀏覽器啟動延遲、GPU 時間或 FPS。

獨立近景交付的 Rocket GLB 有 561,694 個三角面、1,033 個網格零件；Thrust GLB 有 574,662 個三角面、1,023 個網格零件。這組數字描述可編輯展示模型，與整理後網站資料屬於不同資產，不應宣稱全部高面數零件都原樣載入城市。

`visibleGeometryBatches` 計算可見網格的幾何群組，屬於 CPU 端的繪製批次估計；`uniqueGeometryBytes` 加總該品質可見幾何獨立的 attribute／index typed array，排除材質、紋理、JavaScript 物件及其他已快取品質。頁面另顯示 WebGL `renderer.info` 的實際繪製呼叫與三角形；此數字包含地板，並排模式會加總兩版。它們都不是 FPS、GPU 時間、完整顯存占用或城市效能保證。

## 哪些細節值得採用

協調者在實際瀏覽器以同條件高品質外觀及各版原生眼位檢視後，確認新版外觀與座艙均有改善，因此採用新造型配合既有執行期行為。這是人工視覺判定，與效能測量分開；截圖由後續瀏覽器驗收保存。

新模型的近景優勢集中在新發表車的楔形輪廓、銅色玻璃、車燈、輪圈／煞車、尾部噴嘴與風扇分層，以及座艙中的雕塑座椅、縫線／表面分區、閉合方形方向盤、中央螢幕支架、三點式安全帶、紅色門板燈帶和橫置後方氣瓶。網站版本應保留在實際檢視距離能辨識的形體，遠景再透過低階品質省略細小細節。

原執行期的優勢是明確的同步 API、三階幾何快取、有限的共享材質、固定數量噴氣實例及已驗證的操控／相機行為。`createTeslaRoadster()`、`setQuality()`、`update()`、`stats()`、`dispose()` 和相關測試是整合邊界。新資產不應讓載入或品質切換改變輸入擁有權、產生重複動畫迴圈、每幀新建幾何，或把網格精度誤當飛行物理精度。

車輪、尾翼、方向盤及噴氣零件需要保留正確動態父節點與局部軸；量得的新輪胎接點、車體淨空、保守碰撞界線和相機錨點也要同步到契約。單純換外殼而沿用不合適的舊高度，會造成輪胎懸空、底盤穿地或第一人稱相機穿過新車頂。

## 座椅、人物與既有駕駛套件

本次 Roadster 仍是沒有綁定人物的車輛模式。`tools/assets/roadster-driver-fit/` 是針對較早紅色敞篷 `roadster.ts` 的離線固定姿勢候選；它的 SHA 固定來源、接觸檢查及駕駛骨架，不能直接當作目前白色 Tesla 的通過紀錄。

舊候選姿勢的頭頂約為接地平面上方 1.589m，雙手高度約 1.06m；新近景車體的屋頂約為 1.10m、方向盤約為 0.635m。直接平移人物以對齊雙手，會同時破壞骨盆、腿及地板接觸；直接縮小人物也會改變原有身高與肢段比例。新版的座位標記只是美術定位，不是已量測的人物髖骨錨點。

若後續整合駕駛，需要重新製作符合低矮座艙的後仰坐姿、手握修形及腳踏位置，保持原 22 骨骼、inverse bind、單位縮放與肢段長度，再驗證 morph 後蒙皮的實際表面與座椅、車頂、方向盤、中央鞍座、儀表板、腿及踏板的接觸。第一人稱還需避免相機落在人物頭部內。進出車、人物轉向操控與踏板動畫都不在此次已完成範圍內。

## 參考與推定

造型與座艙依 [Tesla 官方 Roadster 頁面](https://www.tesla.com/roadster?redirect=no)、[官方座艙照片](https://digitalassets.tesla.com/tesla-contents/image/upload/f_auto,q_auto/Roadster-03-Carousel-Slide-4-Desktop.jpg) 及 [Tesla 官方設計影片](https://x.com/Tesla/status/2110903770838384773) 建模；資料查閱日期為 2026-10-22。白色／灰色座艙、閉合方形方向盤、中央橫向螢幕與長支架、紅色門框光帶及黑色三點安全帶有直接影像依據。

官方區分雙座 Performance／Thrust 與單座 Rocket；本次飛行版本採單座左駕。清楚可見的官方座艙照片仍是雙座，Rocket 右側氣瓶的具體形狀、數量、固定架與小螢幕的確切位置保留推定標記。車身尺寸、隱藏管路、噴嘴機構及容量／結構沒有原廠 CAD 或工程驗證；這是參考重建模型。

## 驗證方式

工具建置會實際匯入兩版模組，依序建立三階品質，取得 `stats()`、錨點、尺寸與可見包圍盒，最後呼叫 `dispose()`。它同時驗證遞迴相對依賴能解析，並將 JSON 輸出為不需瀏覽器 import assertion 的本機 ES module。

Robson 與 Stanley Park 的 9 項現有道路回歸已通過：保留原始 capture JSON 和所有碰撞、樹木阻擋、停車／倒退、接縫、前進距離及起降判定。`tests/helpers/tesla-historical-capture.mjs` 明確檢查舊車形狀，按新量測的四輪接點沿既有局部上方向調整底盤中心；世界輪胎平面中心、姿態、速度、路面身分和場景三角形不變，每個新輪距仍需實際支持證明。

執行期仍需通過 Roadster 模型、相機品質、控制器與新資產契約的自動化測試，以及專案型別檢查和正式建置。人工 WebGL 驗收需分別檢查三階品質、共同鏡位外觀、兩種原生駕駛視線、轉向／輪胎／風扇／尾翼及噴氣、品質重複切換和 Console 錯誤。比較頁建置成功本身不代表瀏覽器或正式城市畫面已驗收。
