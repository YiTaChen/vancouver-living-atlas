# Titan 地基、真實接觸與事故回饋

2026-10-23（Vancouver）完成整理，開發分支 `codex/rocket-launch-game`。主要回歸與城市驗收於 10 月 22 日完成；恢復工作後追加正常鏡頭觀察，沒有改動已驗收產品來源。

## 這次找到的原因

上一版把道路的高低差當成地基承重強度。Titan 的承重門檻較高，普通路口的幾個百分點坡度便可能被判成「地面垮塌」，接著進入下墜與碰撞破裂；一些沒有接觸一般樓房的路口也因此失敗。先前只選少量低樓重疊的路口，沒有覆蓋這個條件。

[修正前的 20 路口診斷](foundation-baseline.json)保留來源 commit `9c70820`：12 個在觀察期間墜毀，包含 Thurlow／Melville 約 1.8 秒、Nicola／W Pender 約 0.7 秒，以及沒有一般建築 polygon 重疊的 Robson／Gilford。這不是使用者未提供座標的那一枚火箭的精確重播，而是在相似街廓重現的來源程式問題。

地面坡度現在與材料承重分開。搭建支架會調平一般道路；超過 15% 的地形保留有限傾斜並顯示警告。弱屋頂、湖床與水面的原有風險仍使用各自支撐模型。

擴大實景測試後，還發現 Canada Place／Burrard 旁的會展中心使用另一種碰撞幾何：地面承重修正後，外掛助推器以約 0.68 m/s 碰到實際地標網格，仍會走舊的單次致命碰撞。這條路徑也納入本次修正，不能把「一般建築 polygon 沒重疊」當成「沒有其他構造物」。

## 受力與可見事故

Titan 對一般建築、已知地標三角網格及橋梁局部盒體，使用實際表面接觸點與法線，計算相對迎面速度、約化質量的撞擊能量及持續擠壓負荷。沿垂直牆面向上滑動的速度不會全部算成迎面撞擊。有限的分離反力與轉動反應保留手動操作；多個同時接觸分攤持續負荷，高能量撞擊仍可破裂。未知外部碰撞介面保留保守處理。

所有機型在真正地基失效後，也使用有限受力處理已知城市表面的接觸。原始屋頂事故測試另抓到 Atlas 在支撐剛垮、側翼尚未朝旁棟斜牆撞入時，就因零迎面速度接觸被直接判成解體；現在這種擦碰能先承受負荷，保留支撐下沉與自由落體，之後的實際撞地或高速撞擊仍可破裂。沒有使用特定地點、固定無敵時間或刪除障礙物的例外。

畫面會顯示受撞的中央箭體、側助推器、上面級或翼片、障礙物種類、建物高度、相對迎面速度與剩餘結構。接觸處有琥珀色標記、局部凹損、碎塊、短暫火花與灰塵；持續接觸會維持標記，分開後約 1.6 秒消散。首次接觸碎塊由真實表面外側向外飛出，保留切向散布，避免全部射進牆裡被遮住。

建築受損部件以穩定 polygon 身分及原始高度、邊界對應，避免複合樓體選到相同底面但不同高度的部分。Titan 的 96 個建築部件名額拆成 88 個壓力候選與 8 個實際接觸保留名額；已受損部件仍由任務持有並負責還原。

## 倒塌部分仍有碰撞

倒塌後的真實屋體與堆積殘骸可以撞到火箭。地標的任務碰撞三角形與可見模型共用同一個下沉、剪切及局部凹損計算，並更新任務內的空間範圍。落到原範圍外的部分仍可碰撞，原屋頂移走後的空氣則不保留舊表面。

表面移動使用前後三角形相同重心位置的位移計算速度，撞擊採用火箭與表面的相對速度。反力也使用同一相對速度，避免同一次移動牆面接觸在每個步進重複扣除整份撞擊能量。第一次採用表面時沒有先前移動紀錄，因此以零表面速度初始化；靜止殘骸之後仍可被移動的火箭撞上。

移動歷史綁定真正的 FX 變形取樣時鐘。低幀率的一段 0.1 秒可能包含六次固定物理查詢，這些查詢不會把同一段屋頂位移錯除以 1/60 秒。回歸測試包含真實滑動接觸點變化，確認一或六次查詢的屋頂速度與相對撞擊能量一致。

這是有上限的遊戲接觸與破壞模型，不是完整結構工程或所有獨立飛散碎塊的剛體模擬。實際地標碰撞沿用穩定中等模型，Ultra 可見細節使用相同世界座標破壞場。

## 火災與事故觀看時間

碰撞、地基失效後下墜、箭體受熱起火與氣動失效分別顯示各自歷程。上升中撞牆破裂的時間軸不會自動編成「先下墜」，支撐垮塌後的撞擊仍保留地基失效這個起因。

森林造成的外部熱暴露會先升高箭體熱量，再可能出現附著箭體的火焰與煙、結構損傷，最後才可能爆炸。點火階段與飛行階段都有真正的箭體起火警告；引擎正常噴流不會單獨被標成箭體火災。事故或後續爆炸之後仍保留五秒觀看時間，再淡入恢復選項。

這些是配置與記憶體上限，不是手機實機 FPS 保證。任務結束會釋放碰撞快取與繪製副本，還原原始幾何、材質及任務碰撞資料。

會展中心以多個材質網格組成。實景檢查曾抓到只用了 48,903 個頂點，卻因最初的 8 個表面名額耗盡，漏掉實際被撞到的 `meadow-straw` 區域；當時雖然已能升空，該區域仍有約 0.916 m 的可見／碰撞位置差。表面名額因此調整為與可見繪製副本相同的 32，總頂點與雙緩衝位元組上限不增加，另加 12 個小材質區域的採用回歸測試。

## 驗證方法

[城市驗收腳本](../../tools/rocket-ground-contact-acceptance.mjs)使用獨立無頭 Chrome／Metal，從 production 道路圖拾取實際路面，以原本放置與 Auto 指令，呼叫原始 `update(1/60)`。沿用修正前相同 20 個座標，其中有高樓與一般建築重疊、一般建築 polygon 沒重疊、以及會展中心構造物接觸。四個代表點繼續觀察完整任務；每站都逐一列出結果，不把檢查條件全部成立等同於所有站都安全起飛。

觀察器記錄實際輸入、相對撞擊速度、受力、接觸標記、局部變形、繪製後所有權、碰撞快取及回城還原，不指定高度、損壞、起火、飛行階段或成功結果。完整原始 trace 留在忽略的 `work/`；版本庫的精簡報告保留原始檔 SHA256、大小、各站數值、關鍵樣本與每一條斷言。執行前後比較來源 SHA，並拒絕中途 HMR 的結果。

[雙語 48 組版面檢查](foundation-ui-layout.json)是獨立 production React／CSS DOM fixture，包含桌面、615 px、390 px 與手機橫向、手動／自動接觸、火災、事故五秒前及淡入選項；它不代表 WebGL 城市畫面。[真實會展中心 CPU 測試](../../tests/rocket-landmark-collision.test.mjs)使用原始 medium／Ultra 幾何與有明確接觸輸入的破壞場，比較可見及碰撞三角形、舊屋頂空間、落下屋體的真實碰撞與原始資料還原，與自然城市飛行分開。

## 最終結果與可見限制

三種畫質各 **37／37 條件通過，合計 111／111**。Balanced 沿用原始 20 個路口，**20／20** 完成離地後八秒觀察；High／Ultra 各重測四個代表點。四點在三種畫質均抵達 100 km，合計 **12／12 次完整任務**。其餘 16 個 Balanced 位置只做八秒觀察，沒有宣稱完成太空任務。

| 真實路口                              | 三種畫質的模擬飛行時間 | 完成時結構 |
| ------------------------------------- | ---------------------: | ---------: |
| Thurlow／Melville                     |              69.600 秒 |     92.46% |
| Nicola／W Pender                      |              69.483 秒 |     93.06% |
| Robson／Gilford                       |              69.500 秒 |       100% |
| Canada Place／Burrard（會展中心接觸） |              69.950 秒 |     99.18% |

Thurlow／Melville 的建築主體最大實測頂點位移約 94.35 m；火箭保留約 7.54% 的接觸損傷後繼續升空，並非取消周圍建築反應或讓箭體無敵。會展中心觀察到 11 個任務碰撞表面、53,040 個三角形頂點，前後雙緩衝合計 1,272,960 bytes；包含先前漏採用的草屋頂材質區。所有真接觸表面的變形採用檢查通過，原始資料、繪製所有權與回城還原檢查亦通過。

三種畫質均驗證核心與四側助推器同時噴火、地面塵霧散開、四側助推器先分離且核心持續推進，再分離核心與上面級。建造 **6／10／16 秒**、倒數 **5 秒**與既有分級參數保留。

[Balanced 20 點報告](foundation-balanced-runtime.json)、[High 四點報告](foundation-high-runtime.json)、[Ultra 四點報告](foundation-ultra-runtime.json)保留逐站結果及原始 trace 的雜湊與大小。三份報告及事故驗收的 14 個產品來源 SHA 一致，HMR 為零，未捕捉 JavaScript／WebGL shader 錯誤為零。各城市報告仍記錄兩條未帶 URL 的 console 404 訊息；HTTP failure 清單為空、火箭與 worker 資產檢查通過，不能把它們改寫成「所有 console 錯誤為零」。

### 屋頂與森林事故

[同一屋頂與森林事故驗收](foundation-accident-runtime.json) **13／13 通過**，並保存[來源防護紀錄](foundation-accident-source-guard.json)。原始 Atlas 小屋頂位置未更換：支撐在任務 15.55 秒失效，16.55 秒仍隨支撐下沉，17.30 秒處於自由落體，18.45 秒才實際撞地並分成六節。側面接觸已耗散部分能量，本次為 **nonexplosive-impact**，沒有爆炸。撞擊後 4.817 秒仍無恢復選項，5.167 秒開始淡入；面板 opacity 從約 0.041 到 1。

事故腳本依真實殘骸狀態分支：若排定延遲爆炸，就驗證爆炸並從該時刻重新觀察五秒；若未排定，必須確認沒有爆炸事件，再從實際撞擊觀察五秒。這次屋頂實景只覆蓋損壞而未爆炸分支，延遲爆炸重置計時另由狀態／UI 回歸測試覆蓋，沒有宣稱本次屋頂發生爆炸。

同一森林的高風險發射在 15.45 秒真正引燃箭體，之後以正常推力操作上升，19.217 秒在離地約 21.11 m 因火災爆裂；另一個森林 seed 能正常抵達太空。沒有直接指定起火、事故或成功狀態。這些是遊戲中的可重現案例，不代表森林必然爆炸。

### 正常鏡頭的人工檢視

另以正常滑鼠拖曳鏡頭觀察同一 102 m 樓體旁的 Titan，[鏡頭與碰撞紀錄](foundation-contact-camera-observation.json)保留真實輸入、接觸、碎片及 HUD；沒有改動物理狀態。能看見箭體完整、相鄰樓體變形、碎屑及接觸說明。寬追蹤鏡頭下的琥珀細環仍偏小，部分撞點會被前方建築遮住，因此截圖不作「每個環都清晰可讀」的證據。

同一森林另做正常鏡頭觀察，[報告](foundation-forest-camera-observation.json)與[來源防護紀錄](foundation-forest-camera-source-guard.json)保留實際熱量、箭體火災、附著火焰與空中爆裂。頂部「箭體起火」警告可見，但近處樹冠仍遮住部分箭體；不把這張圖當成清楚看見附著火焰的證據。城市幾何仍使用有上限的遊戲破壞場，未宣稱所有屋頂裝飾及每個獨立碎塊都有完整結構模擬。

### 回歸與建置

完整套件 **2,080／2,080 通過**，236 個測試檔、約 118.33 秒，其中包含 **185 項火箭測試**，不另外加總。[完整測試與生成檔還原摘要](foundation-test-summary.json)保留命令與兩份生成 QA 檔案的精確原始位元組／SHA256 還原結果。TypeScript、變更程式檔案 lint／格式、`git diff --check` 與 `build:firebase` 通過。全專案 lint 的既有未更動檔案診斷沿用前輪紀錄；沒有宣稱整個 repository lint 通過。沒有合併 main 或部署。
